# DVC - Data Pipeline Orchestration

Data Version Control (DVC) implementation demonstrating automated data pipeline orchestration with parameter tracking and model versioning.

## Overview

This project showcases DVC (Data Version Control), a powerful tool for:
- Tracking data versions alongside code
- Reproducible ML pipelines
- Parameter management
- Model versioning
- Experiment tracking

## DVC Concepts

### dvc.yaml
The pipeline definition file specifying:
- **Stages**: Individual pipeline steps
- **Inputs**: Data files and dependencies
- **Outputs**: Generated artifacts
- **Commands**: Shell commands to execute
- **Parameters**: Configurable hyperparameters

### dvc.lock
Automatically generated lock file recording:
- Exact versions of all dependencies
- Output hashes for reproducibility
- Execution metadata
- Ensures deterministic runs

## Pipeline Stages

### Data Loading
- Input: Raw dataset
- Output: Processed data

### Model Training
- Input: Processed data, parameters
- Output: Trained model (pickle/joblib)
- Metrics: Performance statistics

### Parameter Tracking
- Learning rate
- Model hyperparameters
- Data splits
- Feature engineering options

## Features

- **Reproducibility**: Guaranteed identical runs given same inputs
- **Efficiency**: Only re-runs changed stages (dependency tracking)
- **Versioning**: Git-based versioning of code, DVC tracks data
- **Metrics Tracking**: Automatic metrics logging
- **Experiment Comparison**: Compare metrics across runs

## Setup

### Initialize DVC

```bash
# Install DVC
pip install dvc

# Initialize in git repository
dvc init

# Add remote storage (optional)
dvc remote add myremote /path/to/storage
dvc remote default myremote
```

### Define Pipeline

Create `dvc.yaml` with stages:

```yaml
stages:
  process_data:
    cmd: python src/process.py
    deps:
      - data/raw.csv
    outs:
      - data/processed.csv
  
  train_model:
    cmd: python src/train.py
    deps:
      - data/processed.csv
      - src/train.py
    outs:
      - models/model.pkl
    metrics:
      - metrics.json
```

## Usage

### Run Pipeline

```bash
# Run entire pipeline
dvc repro

# Run specific stage
dvc repro train_model

# Force re-run
dvc repro --force
```

### Track Data

```bash
# Add data file to DVC tracking
dvc add data/mydata.csv

# Push data to remote
dvc push

# Pull data from remote
dvc pull
```

### Manage Metrics

```bash
# View metrics
dvc metrics show

# Compare experiments
dvc metrics compare
```

## Files

- `dvc.yaml`: Pipeline definition
- `dvc.lock`: Lock file (autogenerated)
- `data/`: Data directory (tracked separately)
- `models/`: Model outputs
- `src/`: Python scripts for pipeline stages

```

```

## Workflow

1. **Define Pipeline**: Create `dvc.yaml` with stages
2. **Execute**: Run `dvc repro` to execute pipeline
3. **Track Results**: `dvc.lock` records execution details
4. **Share**: Commit dvc.yaml/dvc.lock to git, push data via `dvc push`
5. **Reproduce**: Collaborators run `dvc repro` to get same results

## Remote Storage Options

- **Local**: File system (NFS, mounted drives)
- **S3**: Amazon S3 or S3-compatible storage
- **Azure**: Azure Blob Storage
- **GCS**: Google Cloud Storage
- **HDFS**: Distributed file system

## Troubleshooting

**Issue**: Stage not re-running  
**Solution**: Check if outputs already exist and are up-to-date

**Issue**: Data not found  
**Solution**: Run `dvc pull` to download from remote

**Issue**: Lock file conflicts**  
**Solution**: Resolve manually or rerun `dvc repro`

## Best Practices

1. Commit dvc.yaml to git (pipeline definition)
2. Push data to remote storage (dvc push)
3. Document parameters in comments
4. Use meaningful stage names
5. Track metrics automatically
6. Keep pipeline modular
7. Version datasets appropriately
